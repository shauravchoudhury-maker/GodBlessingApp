EverVerse — turning on retention
================================

retention-worker.js is a Cloudflare Worker on a daily cron. Once a day it
erases the text of every Blessing Circle request older than 60 days, and
deletes the replies and any conversation under it. The document itself
stays, with its numbers (tradition, category, language, dates, reply
count), so the Health screen and the yearly transparency report still add
up. This is requirement D4.

WHY 60 DAYS
-----------
Long enough that a person who lost their link for a fortnight can still
find their way back from the front door and read what a guide wrote.
Short enough that a breach, a subpoena or a lost laptop exposes weeks of
private burdens, not years. RETENTION_DAYS can be set anywhere from 30 to
90; the worker refuses anything outside that range.

The person who asked can erase everything sooner, themselves, from the
page their link opens (requirement D5). Retention is the floor under that,
for everyone who never comes back.

SETTING IT UP (Cloudflare dashboard, no tools to install)
--------------------------------------------------------
1. A Firebase service account key. Firebase console -> the gear next to
   "Project Overview" -> Project settings -> Service accounts ->
   "Generate new private key" -> Generate. A JSON file downloads. Keep it
   in Downloads, NEVER inside the GodBlessingApp folder. You need two
   values from it: "client_email" and "private_key". (The same file
   serves identity-worker.js later.)

2. Cloudflare dashboard -> Workers & Pages -> Create -> "Create Worker".
   Name: eververse-retention. Deploy (the hello-world is fine for now).

3. "Edit code". Select everything in the editor, delete it, and paste the
   whole of retention-worker.js. Deploy.

4. The worker's Settings -> "Variables and Secrets" -> Add, four times:
     FIREBASE_PROJECT_ID   type Text     eververse2117
     FIREBASE_SA_EMAIL     type Secret   the client_email from the JSON
     FIREBASE_SA_KEY       type Secret   the private_key from the JSON —
                           copy the whole value between its quotes,
                           
 characters and all; the worker accepts it
     RUN_TOKEN             type Secret   any long random string you invent
                           (30+ characters); it lets you run it by hand
   Optional: RETENTION_DAYS, Text, 60. Deploy / Save.

5. Settings -> "Triggers" -> Cron Triggers -> Add:  20 4 * * *
   (04:20 UTC, every day.)

6. Run it once by hand, from a terminal on your machine:
     curl -X POST -H "Authorization: Bearer YOUR_RUN_TOKEN" https://eververse-retention.<your-subdomain>.workers.dev/run
   It prints one line: ran: {"at":..., "days":60, "seen":0, "expired":0, ...}
   seen 0 is right today — nothing on the site is 60 days old yet. The
   first requests to expire are the September test ones, in November.

7. Open the worker's URL in a browser. It prints "retention: last run ..."
   with the same numbers. That line, and blessing/circle/stats/retention in
   Firestore, are the evidence for requirement D4.

If step 6 says "token exchange failed", the private key was pasted short:
re-copy the whole private_key value. If it says "query failed ... 403",
the service account has no Firestore access: Google Cloud console -> IAM ->
the service account -> role "Cloud Datastore User".

WHAT IT CANNOT DO
-----------------
The update mask on every write is the guard. It can blank `note`, set
`status` to "expired" (only if it was "open") and stamp `expiredAt`. It
cannot touch tradition, category, forGuide, ownerHash, standing, guides,
applications, reports, vouches or bans. Reports are deliberately kept:
they are the record of what was raised and what was done, and they carry
no request text.

SERVICE ACCOUNT SCOPE (requirement S5)
--------------------------------------
This worker needs to read and write requests and their subcollections and
stats/retention. The identity worker needs guides and applications. Until
they have separate service accounts, one account does both; when you
create the second, give each a custom role with only the
datastore.entities.* permissions and nothing else in the project.

EverVerse — Blessing Circle Firestore rules
===========================================

Paste into the Firebase console for `eververse2117`:
  Build → Firestore Database → Rules → Publish.

Keep everything already there. Add this INSIDE the same
`match /databases/{database}/documents { ... }` block — do not replace the
file, or reactions, Twin Track and Second Chance all stop working.


    // ---- Blessing Circle ----
    // A request contains someone's private burden. It is readable ONLY by an
    // approved guide, never by the public, and never listed to anyone else.
    function isGuide() {
      return request.auth != null
        && exists(/databases/$(database)/documents/blessing/circle/guides/$(request.auth.uid))
        && get(/databases/$(database)/documents/blessing/circle/guides/$(request.auth.uid))
             .data.suspended != true;
    }
    function isAdmin() {
      return request.auth != null
        && exists(/databases/$(database)/documents/blessing/circle/admins/$(request.auth.uid));
    }

    match /blessing/circle/requests/{id} {
      // Anyone may ask for a blessing, without an account.
      allow create: if
        request.resource.data.keys().hasOnly(['tradition','category','note','status','replies','flagged','forGuide','createdAt'])
        && request.resource.data.note is string
        && request.resource.data.note.size() > 0
        && request.resource.data.note.size() <= 1200
        && request.resource.data.tradition is string
        && request.resource.data.tradition.size() <= 24
        && request.resource.data.category is string
        && request.resource.data.category.size() <= 24
        && request.resource.data.status == 'open';

      // Only approved guides can read what people have written.
      allow read: if isGuide();

      // A guide may mark it answered, and nothing else.
      allow update: if isGuide()
        && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['status','replies']);

      allow delete: if false;

      // Replies are readable by whoever holds the request's secret id — that
      // is how the person who asked gets back to their blessing without an
      // account and without giving us an email address.
      match /responses/{rid} {
        allow read: if true;
        allow create: if isGuide()
          && request.resource.data.keys().hasOnly(['verseRef','verseText','reflection','guideName','guideUid','createdAt'])
          && request.resource.data.reflection is string
          && request.resource.data.reflection.size() <= 900
          && request.resource.data.guideUid == request.auth.uid;
        allow update, delete: if false;
      }
    }

    // The approved-guide list, which doubles as the guide directory the
    // matcher reads. Profiles are meant to be seen, so they are public — but
    // APPROVAL itself can only be granted from the Firebase console.
    match /blessing/circle/guides/{uid} {
      allow read: if true;

      // An approved guide may edit their own profile, and nothing else. They
      // cannot approve themselves, because create is refused outright: the
      // document has to already exist, and only the console can make it.
      allow create: if false;
      allow update: if
        // a guide edits their own profile — and cannot touch `suspended`
        (request.auth != null && request.auth.uid == uid
          && request.resource.data.diff(resource.data).affectedKeys()
               .hasOnly(['name','tradition','languages','experience','about','capacity','active','updatedAt'])
          && request.resource.data.about is string
          && request.resource.data.about.size() <= 400
          && request.resource.data.name.size() <= 60)
        // or an admin suspends them, and can do nothing else here
        || (isAdmin() && request.resource.data.diff(resource.data).affectedKeys()
              .hasOnly(['suspended','active','suspendedAt']));
      allow delete: if false;
    }

    // Reports. Anyone who received a blessing may file one, without an
    // account — the person who most needs to report is the least likely to
    // have signed up for anything.
    match /blessing/circle/reports/{id} {
      allow create: if
        request.resource.data.keys().hasOnly(['requestId','responseId','guideUid','reason','note','status','createdAt'])
        && request.resource.data.reason is string
        && request.resource.data.reason.size() <= 16
        && request.resource.data.note is string
        && request.resource.data.note.size() <= 500
        && request.resource.data.status == 'open';
      allow read: if isAdmin();
      allow update: if isAdmin()
        && request.resource.data.diff(resource.data).affectedKeys().hasOnly(['status','closedAt']);
      allow delete: if false;
    }

    // Admins. Console-created, exactly like guides.
    match /blessing/circle/admins/{uid} {
      allow read: if request.auth != null && request.auth.uid == uid;
      allow write: if false;
    }

    // Applications go in; nothing comes back out through the client.
    match /blessing/circle/applications/{id} {
      allow create: if
        request.resource.data.keys().hasOnly(['name','email','tradition','role','why','createdAt'])
        && request.resource.data.name.size() <= 80
        && request.resource.data.email.size() <= 120
        && request.resource.data.why.size() <= 900;
      allow read, update, delete: if false;
    }


How to approve a guide
----------------------
1. Read the application in Firestore → `blessing/circle/applications`.
2. Ask them to sign in once at /blessing.html → "For guides" → Sign in with
   Google. They will see "this account is not on the approved-guide list yet"
   — that is expected, and it registers their account.
3. Find their UID in Firebase console → Authentication → Users.
4. Create `blessing/circle/guides/<that UID>` with, say,
   { name: "…", tradition: ["Bible"], approvedAt: "2026-09-09" }.
5. They reload, the queue appears, and they fill in their own profile from
   inside the app — lived experience, languages, how many at once.

Note the asymmetry: a guide can edit their profile but can never CREATE the
document, so approval is impossible from inside the app. Only the console
grants it.

There is no way to do step 4 from inside the app, on purpose. Adding a guide
should require deliberately opening the console.


What this protects, and what it does not
----------------------------------------
PROTECTED: nobody without an approved guide account can read a single
request. The collection cannot be listed, searched or enumerated by the
public, and requests can never be deleted or edited after the fact.

NOT PROTECTED, by design: anyone holding a request's link can read the
replies to it. That is the trade for not collecting email addresses — the
secret link IS the credential, exactly as it is for a password-reset URL.
The person is told plainly to keep it.

STILL YOUR JOB: an approved guide can read every open request. Approval is
therefore a real trust decision, not a formality. Approve slowly.


Moderation
----------
Three layers, in descending order of how much good they do.

1. PREVENT. A reply is checked before it can be sent. Contact details, links,
   requests for money, and anything telling a person to stop medical treatment
   are refused outright — those are not judgement calls. Softer language
   ("cure", "you deserve this", "I guarantee") warns once and sends on a
   second press. Tested against fourteen cases including genuine replies that
   mention a doctor or money worries, which pass clean.

2. REPORT. One tap under any received blessing, seven reasons, no account.

3. ACT. `blessing/circle/reports` is readable ONLY by an admin. Suspending
   sets `suspended: true`, and isGuide() checks it — so access to the queue is
   gone on the guide's very next request, not at some later cleanup.

To make yourself an admin, create `blessing/circle/admins/<your UID>` in the
console. Same as guides: there is no way to do it from inside the app.

Note what a guide CANNOT do: touch their own `suspended` field. The rule lets
them edit name, tradition, languages, experience, about, capacity and active —
and nothing else. Only an admin writes `suspended`, and an admin can write
nothing else on that document.

Replies are immutable — no update, no delete, by rule. Whatever was actually
written is still there when you come to look at it, which is the only reason a
report is worth filing.
